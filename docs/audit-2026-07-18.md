## 一、后端审计（backend/app）

### 🔴 高危

1. **`read_text_asset` 工具 100% 崩溃（已实测复现）** — `agent/tools/asset_tools.py:280,311` 引用了 `Asset.updated_at`，但 `models.Asset` 没有这一列，两条路径均抛 `AttributeError`。agent 读小说/脚本正文必挂，测试未覆盖。修复：改用 `created_at` 或补列。
2. **CORS 全开放 + 全 API 无鉴权** — `app/__init__.py:23-29` `allow_origins=["*"]`，任意恶意网页可调用本地 8765 后端：创建 agent 任务烧 API 额度、读写全部项目数据。修复：收紧 origins 或加本地 token。
3. **tool_error 恢复路径 KeyError** — `routers/agent.py:590-597` → `agent/runtime.py:1064`：重启后重建的 `pending_request` 缺 `step_id`/`tool`/`params`/`error`，"工具失败→暂停→重启→重试"链必崩。
4. **step 持久化与记忆压缩冲突** — `routers/agent.py:735-768` × `agent/runtime.py:870`：`_persist_steps` 按下标覆写且不更新 `step_number`，压缩后 DB 记录错位污染，`_step_count` 重置产生重复编号。
5. **资产 URL 路径遍历** — `agent/asset_intelligence.py:151-161`：`/files/../../dramaforge.db` 可读出本地任意文件，base64 后外发给 LLM provider。修复：basename + `is_relative_to` 校验。
6. **短 API key 明文泄漏** — `models.py:298,354,480`：key ≤ 8 字符时 `to_dict(mask_key=True)` 原样返回明文。

### 🟡 中危（摘选）

- `list_tasks` N+1 查询（`models.py:176-181`）
- 记忆压缩后成本/token 统计回退，用户看到成本"越跑越少"（`agent/memory.py:118-124`）
- LLM 输出解析失败无退避，最多白烧 30 次全量 prompt（`agent/runtime.py:217-226`）
- 事件日志只增不清，内存随任务数线性增长（`agent/events.py:108-151`）
- LLM 响应非 JSON 时任务直接 FAILED；`int(None)` TypeError；streaming 无重试（`agent/openai_llm_client.py:150,227,251`）
- 视频生成 404 静默伪造成功，返回不存在的 `dev-fallback.mp4`（`routers/media.py:142-154`）
- 生成中删除资产 → `.one()` 抛 `NoResultFound` 任务崩溃（`agent/media_assets.py:146`）
- media "recovery" 实为同参数立即重打一次付费请求（`agent/runtime.py:1014-1029`）
- 上传无大小限制、可传 `.html`/`.svg` → 存储型 XSS（`routers/uploads.py:19-55`）
- import 时执行 DDL，迁移逻辑三处重复（`models.py:227-237,575-589`、`database.py:80-145`）
- 重启后 `running` 僵尸任务无法 resume（`routers/agent.py:928-943`）
- `UpdateTextAssetTool` 的 artifacts 同步是死代码（`agent/tools/asset_tools.py:423-446`）

### 🔵 低危（摘选）

- 422 handler 可能返回不可序列化对象；`on_event("startup")` 已弃用
- 硬编码价格表过时，成本展示系统性偏低
- `task_profiles.py:259` 混入乱码 `"鍔熷か"`；关键词重复
- 测试直接操作真实 `dramaforge.db`，污染开发库（`tests/conftest.py:47-91`）
- 超长函数：`runtime.step()` ~265 行、`_sanitize_optimized_prompt` ~165 行、`routers/agent.py` 996 行单文件
- 仓库卫生：backend/ 根目录 10+ 调试残留文件、`dramaforge.db*` 入库
- `llm_providers.py`/`media_providers.py` 两个 410 行文件几乎完全重复

## 二、前端功能流程与代码质量审计

### 🔴 高危

1. **`LOGICAL_STEPS` 双定义不一致** — `App.tsx:52-59`（6 步）vs `hooks/useTaskExecutor.ts:8-17`（8 步）：auto 模式跳过道具/场景设计；`PROP_DESIGN` 完成后 `indexOf = -1` 流程回退到预处理重新扩写。
2. **取消任务后 500ms 自动重启** — `useTaskExecutor.ts:41` + `App.tsx:690-697`：auto 模式点取消，任务静默重跑，浪费 LLM 费用。
3. **SSE 事件清单缺 12 种** — `agent/agent-stream-manager.ts:34-55` 缺 `tool_error`、`conversation_continued`、`media_recovery_*`、`asset_inspection_*` 等，EventSource 静默丢弃 → 错误恢复卡成死代码、多轮对话记录丢失。
4. **角色参考图 blob: URL 失效** — `hooks/useTaskActions.ts:175` 把浏览器 blob URL 发给后端当 `ref_urls`，后端无法下载，参考图静默失效且刷新后成死链。
5. **画布切项目竞态 + 空数组覆盖保存** — `use-canvas-store.ts:1976-2017`：慢响应覆盖新项目；`set({nodes: []})` 触发 600ms 后空数组全量 PUT，可能清空项目节点；保存定时器是模块级单例，跨项目互相 clearTimeout 丢编辑。

### 🟡 中危（摘选）

- `pageKey` 是死状态（`App.tsx:96`）
- Sora 提示词优化按钮与普通优化是同一个函数（`App.tsx:1052-1053`）
- 画布视频生成硬编码 `style='cinematic'`、`language='zh'`，错误文案全写成 `'optimizing prompt'`（`use-canvas-store.ts:868-924`）
- `getProviderForStep(...)!` 非空断言链 7 处，未配置 provider 时报错不可操作
- `handleEnterAgentMode` 在 setState updater 内执行副作用，StrictMode 下产生双 id
- `executeTaskStep` 依赖 `tasks` 导致链式重建 + 画布整体重渲染 + 重复调度
- 单体重生成基于任务快照写回，覆盖生成期间的并发编辑（`useTaskActions.ts:222,250,284`）
- `cost_update` 累加与 SSE 重连 rehydrate 重复计费
- 超大文件：`ApiSettingsModal.tsx` 2291 行、`use-canvas-store.ts` 2034 行、`CanvasNode.tsx` 1996 行
- `tsconfig.json` 未开 `strict`，全库 `as any` 75+ 处
- `apiClient.request` 无超时、不支持 AbortSignal
- `alert()` 11 处与 toast 系统并存

### 🔵 i18n

- **29 个代码中使用的 key 在四语言包中全部缺失**，UI 直接显示英文 key 原名（`completed`、`noApiKey`、`settings`、`storyboard`、`sensitiveFilterReport` 等）
- ja 缺 26 key、ko 缺 17、en 缺 9；硬编码中英混排多处

## 三、前端美化审计

**一句话诊断**：骨架很好（CSS 变量、双主题雏形、动效库、reduced-motion 关怀都有），皮肤没统一——三套互相漂移的 design token、400+ 处 TSX 硬编码色值、无阶的字号/圆角/阴影，项目列表（浅色）与画布（深色）视觉割裂。

### 🔴 高影响

1. **三套 design token 并存且数值漂移** — `index.html:96-113` vs `canvas.css:2-48` vs `theme.ts:39-55`：深色 page 色 `#0b1020` vs `#0f141d`，`--ease` 同名不同值。收敛为单一 token 源。
2. **TSX 硬编码 hex 400+ 处**（BigShotDetailModal 58 处、NewTaskModal 42 处…），全部浅色系，永远无法适配深色。
3. **`App.tsx:925` 正文 `#c7d2fe` 淡蓝字显示在白半透明卡片上，几乎不可读**（实际可用性 bug）。
4. **`NewTaskModal.tsx:99-119` 选中态层级反转**：选中标题色比未选中更浅，选中/未选中背景几乎无差别。
5. **`index.html` `lang="en"` + 只加载 Inter**：中文回落系统字体，渲染不可控。改 `lang="zh-CN"` + 中文字体栈。
6. **Tailwind Play CDN 生产环境运行**：1.5MB 编译器、首屏样式闪变、断网即崩塌。迁移到构建期 Tailwind。

### 🟡 中影响

- 字号 21 种（含 8/9px 低于可读下限）→ 收敛 7 级；圆角 17 种 → 4 级；阴影 20 种手写 → 3 级 token
- 字重 650/750/850 浏览器合成 → 统一 500/600/700/800 或引 variable font
- 三条全局横幅固定像素 top 手算堆叠（`global-agent-banners.css`）→ 改 flex 容器
- z-index 无规划（toast 200 / 桌宠 10000 / 弹窗 50/100）→ 6 级 token
- 两个"新建项目"弹窗并存样式不一致（`App.tsx:934` vs `NewTaskModal`）
- `TaskCard` 封面默认 `opacity-50` 灰蒙蒙；占位图用外网 `picsum.photos`
- 项目列表（浅色）与画布（深色）主题割裂，无全局切换

### 🔵 低影响

- `:focus-visible` 仅 20 处；整卡 `div onClick` 无键盘可达性
- 可点击区域最小仅 24×24px；次要按钮对比度 3.8:1
- 全项目仅 6 个 `@media` 断点；toast 位置与画布工具按钮遮挡风险
- agent 任务空态只有一行灰字；动效时长十余种混用
