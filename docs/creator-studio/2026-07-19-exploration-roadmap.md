# DramaForge 创作者价值探索路线图

日期：2026-07-19　分支：`explore/creator-studio`

## 0. 背景问题

创作者可以用 ComfyUI、libTV+codex 等通用工具拼凑出类似能力，
本项目的差异化价值是什么？如何让用户**做出完整的短剧成品**而不是一堆素材？

## 1. 竞品与现状对比

| 维度 | ComfyUI | libTV+codex（通用 agent 驱动工具） | DramaForge 现状 |
|---|---|---|---|
| 节点编排 | 强，但面向技术用户 | 无 UI，靠对话驱动 | 有（无限画布），面向创作者 |
| 短剧领域结构（剧本/角色/分镜/集） | 无，要自己拼 | 每次重新教 | **有（pipeline 节点、drama task）——核心资产** |
| 资产一致性（角色跨镜头） | 靠用户自己管 LoRA/种子 | 无持久关系 | 有部分（参考边、资产版本、inspect_asset） |
| 成片（剪辑/字幕/配音/导出） | 无 | 无 | **缺失——最大短板** |
| 质量控制闭环 | 无 | 无 | 有部分（资产检查），无打分/自动重试 |
| 多 agent 分工 | 无 | 单 agent | 单 agent runtime，职责混合 |

结论：本项目的价值不在"又一个节点画布"，而在于**领域化**——
短剧结构是一等公民、领域知识内置、创作者只做决策不做拼装。
竞品拼的是"能力"，我们要拼的是"从文字到成片的生产线"。

## 2. 价值主张（一句话）

**短剧导演工作台**：小说/创意 → 剧本 → 角色/场景资产（一致性锁定）→ 分镜 → 镜头视频 → 配音字幕 → 剪辑成片，全流程领域知识内置，多 agent 分工协同。

## 3. 探索 Track（按价值/成本排序）

### Track A — 成片工作台（补"最后 100 米"）★ 最高优先级

现状：生成的是散装镜头素材，用户还得去剪映才能出片。没有成片能力，"做完整短剧"就是空话。

- 时间线视图：镜头排序、时长、转场、字幕轨、配音轨、BGM 轨
- 后端 ffmpeg 合成导出 mp4（镜头已在后端可及，合成是自然延伸）
- 里程碑：单集 3~5 个镜头 → 一键导出带字幕/BGM 的 mp4

### Track B — 多 agent 协同骨架 ★ 差异化核心

现状：单 agent runtime，编剧/导演/美术/质检职责混在一起，长任务易跑偏。

建议架构（复用现有模块，不做大重构）：

```
Orchestrator（编排器，黑板式共享状态 = drama task + assets 表）
├── 编剧 agent   — 大纲/分场/剧本/分镜文本（task_profiles + prompt_engineering）
├── 导演 agent   — 运镜/节奏/时长决策，把分镜翻译成镜头参数
├── 美术 agent   — 角色/场景/道具资产生成与一致性守门（asset_intelligence 已有雏形）
├── 质检 agent   — 按 rule pack 对产出打分，不合格自动打回重生成（inspect_asset 升级）
└── 剪辑 agent   — 成片编排（依赖 Track A 的时间线）
```

- 每个 RoleAgent = 独立 system prompt + 受限工具子集 + 专属 rule pack
- agent 间通过黑板（资产/任务状态）+ 显式消息协作（user_messages.py 已有通道）
- 画布即各 agent 产出的可视化，用户可随时人工接管任一环节
- 里程碑：编剧→美术→质检三方协同跑通"一个分镜从文本到过审镜头"的闭环

### Track C — 角色/世界观一致性系统

现状：一致性靠参考图硬传，跨镜头脆弱。

- 角色卡：face anchor + 参考图集 + 固定种子/指纹，跨镜头锁定
- 场景卡：七层结构已有（SceneAsset），加一致性评分
- 质检 agent 的一致性打分反馈环（依赖 Track B）

### Track D — 引导式创作流（页面/操作层）

现状：画布自由但新用户面对空画布不知从何开始；项目层与画布层数据有重复。

- "新建短剧"向导：创意 → 大纲 → 集数 → 每集自动展开为画布生产线
- 项目结构改为：短剧 > 集 > 画布（现在是平铺项目）
- 每集一条看板视图：剧本 → 资产 → 分镜 → 镜头 → 成片（进度一眼可见）
- 画布保留为镜头级工作台，不做成唯一入口

### Track E — 操作细节（顺手做）

- 批量重生成、失败诊断（error-recovery-card 已有，推广到所有节点）
- 生成前成本/时长预估（供应商模型单价 × 镜头数）
- 角色库/场景库跨项目复用（资产库升级为全局库）

## 4. 明确不做的

- 不做通用节点图（那是 ComfyUI 的战场，拼不过也不该拼）
- 不碰模型训练/LoRA 托管（重资产、合规风险）
- 不做多人实时协同（当前阶段投入产出比低）

## 5. 建议的第一个迭代（2 周颗粒度）

1. Track B 骨架：Orchestrator + 编剧/美术/质检 三个 RoleAgent 最小闭环（后端为主）
2. Track A 最小版：镜头列表 → ffmpeg 拼接导出（无转场无字幕先跑通）
3. Track D 的"新建短剧"向导第一屏（把入口从空画布改为有轨道的生产线）

验收标准：用户输入一段小说，选择"生成第 1 集"，
得到一段带角色一致性的、可下载的 mp4 成片（哪怕只有 30 秒）。
