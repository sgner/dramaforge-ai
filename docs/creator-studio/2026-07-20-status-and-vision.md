# DramaForge 现状、发展路线与最终交付形态

日期：2026-07-20　分支：`explore/creator-studio`（基线：`recovery`）
关联文档：`docs/creator-studio/2026-07-19-exploration-roadmap.md`（探索路线图）

---

## 1. 背景与问题定义

创作者用 ComfyUI、libTV+codex 等通用工具也能拼凑出 AI 视频生成能力，
但"短剧"所需的领域知识（剧本结构、角色一致性、分镜语言、成片合成）
都要用户自己补齐。DramaForge 的差异化定位：

> **短剧导演工作台** —— 从一段文字到可下载成片的完整生产线，
> 领域知识内置、多 agent 分工协同、创作者只做决策不做拼装。

## 2. 当前已完成

### 2.1 画布单节点体验修复（recovery 分支，已验证）

围绕"单独使用上传节点"的一系列根因修复：

| 问题 | 根因 | 修复 |
|---|---|---|
| 上游 401"无效的令牌" | 提示词优化走前端直连，store 里的 apiKey 为空/过期 | 新增 `POST /api/llm/generate` 后端代理，key 只存后端 DB |
| 单节点生成被改写提示词 | 三处单节点路径隐式调用 LLM 优化 | 单节点原样使用用户 prompt；优化仅保留为 pipeline 显式步骤 |
| 图生图 400"至少需要一张图片" | ①后端只把 URL 文本拼进 prompt ②节点存的是浏览器 blob: URL | 参考图真实传递（本地转 base64 data URI，image 字符串字段）；四个图片入口改为先上传后端再替换 URL |
| 单节点生成六宫格 | 复用了标准流程的 Six-Panel 故事板模板 | 新增 `generateImageDirect`，单节点不套任何模板 |
| 第二次输入被第一次覆盖 | ComposerPanel 水合时机 + `_assetPrompt` 优先级错误 | 仅切换节点时水合，用户草稿优先 |
| 无法换图 | 有图状态只有删除按钮 | 悬停"重新选择图片"按钮 |

上游网关契约均为实测（`api.seedance.nz`）：image 字段为字符串（数组 400）、
data URI 可用、多图逗号拼接、异步任务轮询取 `data.result_url`。

### 2.2 多 agent 工作室骨架（explore/creator-studio 分支）

```
POST /api/studio/character-cards   参考图 → 角色卡（vision LLM 提取身份指纹）
POST /api/studio/shots             单镜头闭环（编剧→美术→质检，最多 3 轮打回重试）
POST /api/studio/episodes   (202)  一段故事 → 整集 mp4（异步任务）
GET  /api/studio/episodes/{id}     轮询：phase/每镜头进度/最终结果
GET  /api/studio/character-cards   项目角色卡列表
POST /api/studio/export            任意镜头序列 → ffmpeg 合成 mp4
```

五个 RoleAgent，职责互斥，不共享上下文，通过黑板（trace + 结构化产物 + 显式反馈）协作：

- **导演**（`director.py`）：把故事拆成 3~8 个镜头 brief（叙事递进，不写生成 prompt）
- **编剧**（`studio.py`）：brief(+质检反馈+角色身份块) → 单镜头生成 prompt
- **美术**（`studio.py`）：走媒体代理生成镜头图（角色卡参考图 i2i 锁形象），落 Asset
- **质检**（`studio.py` + `character_cards.py`）：视觉检查 + 逐卡一致性比对（score≥0.6），
  不过审的具体问题回传编剧重试
- **剪辑**（`studio_export.py`）：过审镜头规整为 1280x720/30fps 片段，concat 成整集 mp4

前端：`components/StudioPanel.tsx` 工作室面板（项目列表页场记板图标进入），
故事输入 → 角色卡多选 → 3s 轮询每个镜头的 agent 状态 → 成片播放/下载。
四语言 i18n 完整。

## 3. 已知限制

1. 角色卡建卡和质检依赖 vision 能力的 chat 模型，未配置时闭环会在质检步报错
2. 任务注册表纯内存态，后端重启任务丢失
3. 整集为串行逐镜头（控制供应商速率），无并行
4. 成片无字幕/配音/BGM/转场（Track A 完整版未做；逐镜头时长已支持）
5. ~~建卡只有 API~~（已解决：角色卡阶段内建建卡表单，选资产参考图一键建卡）
6. 质检标准是通用资产标准（CHARACTER_STANDARD），还没有"镜头级"标准（构图、运镜、时长）
7. 画布（节点编辑器）与工作室（生产线）目前是两套入口，数据未打通

## 4. 之后的发展路线

### Phase 1 — 真机联调与可用性（当前迭代，最高优先）

目标：创作者能真实跑出一集 30 秒成片。

1. 端到端真机验证：配置 vision 模型，跑通 建卡→整集→下载 全链路，修实测问题
2. ~~面板内建角色卡~~（已完成：角色卡阶段内建建卡表单——角色名 + 项目图片资产多选 + LLM 供应商选择，调建卡 API 后刷新列表）
3. 镜头结果回看：面板里能看每个镜头的图和打回原因（trace 已有，需 UI 呈现）
4. 失败恢复：单镜头失败可单独重跑，不必整集重来

### Phase 2 — 成片完整版（Track A 完整形态）

1. 时间线视图：镜头排序/删减、单镜头时长调整
2. 字幕轨：从剧本对白自动生成 SRT，ffmpeg 烧录或软字幕
3. 配音轨：TTS 供应商接入（按角色选音色，角色卡扩展 voice 字段）
4. BGM 轨 + 简单转场
5. 导出档位：720p/1080p、码率选择

### Phase 3 — 引导式生产线（Track D）

1. "新建短剧"向导：创意 → 大纲 → 集数 → 每集自动展开
2. 项目结构改为 短剧 > 集 > 生产线，每集一条看板（剧本→资产→分镜→镜头→成片）
3. 画布与工作室打通：工作室产物以节点形式落到画布，画布成为镜头级精修台
4. 全局角色库/场景库：跨集、跨项目复用角色卡

### Phase 4 — 质量与成本（Track C 深化 + Track E）

1. 镜头级质检标准：构图/运镜/时长/敏感内容，rule pack 可配置
2. 一致性量化报表：整集角色一致性分数
3. 生成前成本/时长预估（模型单价 × 镜头数 × 预计轮次）
4. 镜头并行生成（供应商限流策略内）
5. 任务持久化（注册表落 DB，重启可恢复）

### 明确不做（维持路线图结论）

- 不做通用节点图（ComfyUI 的战场）
- 不碰模型训练/LoRA 托管
- 不做多人实时协同

## 5. 最终交付形态

### 一句话

**输入一段小说，得到一个角色一致、带字幕配音、可直接发布的短剧成片。**

### 用户旅程

1. **建剧**：点"新建短剧"，粘贴小说或一句话创意，导演 agent 出大纲和分集规划
2. **定角色**：从小说自动抽取角色列表，为每个角色上传/生成参考图，一键建角色卡
   （身份指纹 + 音色）；创作者确认或微调
3. **生产**：点"生成第 1 集"，看板上实时看到五个 agent 的工作流：
   导演拆镜头 → 编剧写 prompt → 美术出图 → 质检打分（不合格自动打回）→ 剪辑合成。
   创作者可在任一环节介入：改剧本、换参考图、手动重跑某个镜头
4. **精修**：时间线上调镜头顺序/时长、改字幕、换配音、加 BGM；
   需要重生成某个镜头时跳进画布做镜头级精修（图生图/局部重绘）
5. **交付**：导出整集 mp4（带字幕配音），或按平台规格（抖音 9:16/B 站 16:9）分别导出；
   角色卡入库，第 2 集直接复用

### 产品界面结构

```
短剧列表
└── 短剧（大纲、世界观设定、角色库）
    └── 集（看板：剧本 → 资产 → 分镜 → 镜头 → 成片）
        ├── 生产线视图（agent 实时进度，默认）
        ├── 画布视图（镜头级精修，现有无限画布）
        └── 时间线视图（剪辑/字幕/配音/BGM）
```

### 系统形态

- **五个 RoleAgent**（导演/编剧/美术/质检/剪辑）常驻，编排器调度，
  黑板共享项目状态；新职责（如音效 agent）按同一模式挂接
- **角色卡/场景卡**是一等公民资产，跨集跨项目复用，
  一致性由质检 agent 的量化评分兜底
- **供应商无关**：LLM/图像/视频/TTS 全部走统一代理层，
  用户只需在设置里配 key，替换供应商不改业务流程
- **交付物**：整集 mp4（多规格）+ 可复用的角色/场景资产库

### 与竞品的最终差异

| | ComfyUI | libTV+codex | DramaForge |
|---|---|---|---|
| 面向 | 技术用户 | 开发者 | **短剧创作者** |
| 领域知识 | 用户自备 | 每次重教 | **内置（agent 职责 + 模板 + 质检标准）** |
| 角色一致性 | 手动管理 | 无 | **角色卡 + 质检闭环** |
| 成片 | 无 | 无 | **时间线 + 字幕配音 + 多规格导出** |
| 质量保障 | 无 | 无 | **质检 agent 自动打回重试** |

## 6. 产品融合修订（2026-07-20 补充）

经外部产品建议评审，确认定位进一步收敛为：

> **短剧的连续性与交付系统。** ComfyUI / libTV / Codex 解决"怎么生成"，
> DramaForge 解决"生成什么、为什么这样生成、如何保持一致、如何反复修改并最终交付"。

与本项目既有实现的融合结论：方向一致，技术底座已搭好一半，
真正的新增是 **Story Bible（故事圣经）中心对象** 和 **人审层（审片台）**。

### 6.1 优先级修订（替代第 4 节的 Phase 顺序）

1. **Story Bible**：角色卡/场景卡升级为圣经实体的引用；镜头生成时记录实体关联
   （依赖图）；修改实体时做**只读影响分析**（"该角色出现在 N 个镜头"），
   重生成由用户逐个触发（不做自动传播——烧钱且不可控）。
2. **审片台（人审层）**：镜头加 review_status（待审/通过/退回/锁定）+ 多版本保留；
   critic 自动初筛，人审终审。审片台 > 新建项目向导（先把单集生产做可靠，再包装入口）。
3. **首页"今天要做什么"**：从 review_status / 任务状态聚合"上次做到哪、下一步做什么"。
4. **交付中心**：字幕/配音/BGM/多规格导出（原 Phase 2 内容）。
5. **工程模式**：无限画布与 Agent ThoughtStream 保留，但不作为默认入口。

### 6.2 连续性检查分层（修正"全押 vision LLM"的做法）

- **结构化比对为主**：Story Bible 字段 diff（服装、道具、时间、天气），便宜且确定性强；
- **视觉抽检为辅**：现有逐卡一致性比对（score≥0.6），做初筛和人审标记，不做终审。

### 6.3 已落地的 Story Bible 最小实现（本迭代）

- 镜头资产生成时写入 `extra.brief` + `extra.character_card_ids`（依赖图）；
- `PUT /api/studio/character-cards/{id}`：更新身份指纹，返回受影响镜头列表；
- `GET /api/studio/character-cards/{id}/impact`：只读影响分析；
- `POST /api/studio/shots/regenerate`：用镜头存的 brief + 角色卡关联一键重跑闭环；
- 测试 5 例（backend/tests/test_story_bible.py），后端全量 732 passed。

下一步：审片台（review_status + 多版本 + 人审 UI）。

### 6.4 已落地的审片台后端（本迭代）

人审层已从规划变为现实（commit 0c089d8）：

- **critic 降为初筛**：闭环结束后镜头自动写入 `extra.critic_status` + `review_status=pending_review`，
  不再"自动过审即交付"；
- **人审终审**：`POST /api/studio/shots/{id}/review`（approve / reject / lock / unlock + 备注）；
- **版本分组**：`GET /api/studio/shots` 按 brief 自动归并多版本（version x/y），
  配合作废重生成（`/shots/regenerate`）形成"退回 → 新版本 → 再审"的循环；
- 测试 5 例（backend/tests/test_review_desk.py），后端全量 737 passed；
- 前端审片台（StudioPanel 结果区升级）开发中。

### 6.5 首个 demo 的前提与路径（2026-07-20 实测评估）

1. 硬前提：供应商配置一个支持视觉（vision）的 chat 模型

2. 路径：启动后端 + 前端 → 项目列表页场记板图标进工作室 → 粘小说 → 生成整集；
3. 首跑建议 3 镜头小集，目标是暴露真实问题（vision 能力、质检打回率、生成时长），
   预计 30 分钟内可见第一支真实成片。

- 测试 +4（tests/studio-panel.test.tsx 14→18 用例），前端全量 334 passed。

### 6.7 工作室三台定位（2026-07-20 产品方向调整）

用户决策：**工作室是最终成品地**（导演台 + 资产智能编排 + 内置剪辑台），
**首页项目是素材车间**（只负责生成资产）。本迭代已落地：

- **首页方向调整**：工作室入口卡副标题改为"导演台 · 智能编排 · 剪辑台"；
  项目区新增"素材车间"副文案（`projectsWorkshopHint`）；hero 描述同步，四语言；
- **剪辑台（StudioPanel 新阶段 timeline）**：项目全部媒体资产入库挑选 →
  时间线排序（上移/下移/移除）→ 逐镜头秒数 → 导出 mp4（逐镜头 durations）；
- **资产智能编排（MVP）**：`POST /api/studio/arrange`——导演 LLM 对选中资产
  按叙事排序并给出每镜头 sec/caption；LLM 漏项按原顺序补齐、输出不可解析时
  降级为原顺序（建议是建议，不阻塞手动编排）；前端"智能编排"按钮一键重排回填；
- **后端**：`export_sequence` 支持逐镜头 `durations`（缺省回落 sec_per_image）；
- 测试：后端 763 passed（新增 arrange 5 例 + durations 3 例）；
  前端 340 passed（剪辑台 6 例，studio-panel 18→24）。

**首页布局重构（同日跟进）**：仅改文案不够，布局本身未表达"项目产素材、工作室出成片"
的关系。已重构为：品牌 hero → **深色"成片工作台"横幅**（对齐 StudioPanel 暗色配色，
与白底项目区形成视觉区分；左标题副标、中部三步流程条 素材车间产料→工作室编排剪辑→
导出成片、右侧"进入工作室"CTA）→ **素材车间**项目网格（标题正名 workshopTitle，
每个项目卡 hover 出现"去工作室成片"直达按钮，点击以该项目 projectId 打开 StudioPanel；
顶部 CTA 打开则面板内自选项目）。前端 343 passed（+3：横幅渲染/项目卡直达/顶部 CTA）。

至此工作室形成完整叙事：**素材车间产料 → 导演台自动生产线 / 剪辑台手动编排 → 成片导出**。
后续迭代（交付中心）：字幕轨/配音轨/BGM/转场/多规格导出、时间线拖拽排序、
caption 烧录为字幕。

**三台定型（同日四次跟进，按用户决策）**：工作室收敛为三个 tab——
- **导演台**（默认）：以脚本 json（drama-task 的 bigShots/order/charactersInvolved）为
  剧集结构事实源，同步画布资产（rebuild-from-nodes）→ 剧本结构表
  （序号/场景/出场角色/故事板/视频状态/审片状态）→ 审核（通过/退回，复用 review API）
  → 补缺指路（缺失镜头提示去素材车间生成）→ **"送入剪辑台"**把有序镜头序列灌入时间线；
- **剪辑台**：时间线由导演台预填（不再从空开始/不再全资产平铺）；补充素材 bin 默认折叠、
  只显示未入轨资产；快捷键补齐（空格播放、←→ seek、Shift+←→ 切镜头、Home/End、
  Del 删除、Ctrl+↑↓ 移动、± 缩放、Ctrl+E 导出）+ 底部快捷键提示条；
- **成片库**：不变。
- **角色卡阶段移除**：一致性由素材车间参考图 i2i/i2v 直给生成模型保证，
